# 量潮写作云 - 产品需求文档

## 主线故事

小陈是 CEO 助理，老板在内部发了一篇关于产品理念的随笔，小陈要把它改写成对外公众号文章。

### 第一次

他把文章粘贴到写作云，系统拆出叙事结构。他一边看一边想：原来老板是这样推演的。关掉分析面板开始改写，写到竞品部分卡住了——翻出结果对照调整。定稿后老板改了两处。

### 第二次

他又丢进去一篇。系统拆出来，他扫了一眼发现结构似曾相识——和上一篇都是先承认困境再推演。他没看分析面板就动笔了。

### 第三次

他不再打开分析面板了。老板改了什么地方、习惯用什么类比、逻辑跳跃怎么搭桥——他已经能自己说出来。新来的实习生问他"老板的风格是什么"，他直接讲了一遍。

团队叙事风格的一致性由此开始：不是靠模板，而是靠方法内化到人。

## 用户需求

### 叙事分析

作为 CEO 助理，我希望把 CEO 的内部文章导入系统，系统自动拆解出叙事结构，这样我就能理解他的推演方式。

**验收标准：**
- 支持粘贴或上传 CEO 的原始文章
- 自动识别文章的叙事单元（起承转合等）
- 展示每个单元的逻辑功能：叙事动作、严密性支撑、逻辑效果
- 原文按段落切块，分析结果与原文段落对应排列

### 风格积累

作为 CEO 助理，我希望系统能积累多篇文章的分析，逐渐勾勒出 CEO 一贯的叙事风格，这样我就能越用越顺手，不再每次从零学起。

**验收标准：**
- 每篇文章的分析结果可存档
- 支持跨文章对比叙事结构异同
- 自动提炼高频叙事手法

### 团队传承

作为已经内化了方法的助理，我希望我能把分析结果和方法教给新成员，这样团队不会因为人员流动而丢失风格一致性。

**验收标准：**
- 分析结果可分享给他人
- 支持导出风格总结文档供新人学习使用

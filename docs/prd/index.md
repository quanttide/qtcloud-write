# 量潮写作云 - 产品需求文档

## 主线故事

创始人最近在整理自己的文章。他把随笔丢进写作云，系统一拆，他看到了自己的几种写法——有的先承认困境再推演，有的直接抛判断再举例。原来自己有这么多样式。

他让助理也用上。

助理第一次用，是把老板的文章粘贴进去。系统拆出叙事结构，他边看边想：原来老板是这样推演的。关掉面板开始改写，写到竞品部分卡住了——老板用了"过时兵种"的类比，他不知道怎么转成客户语言。他翻回分析结果，对照原文的逻辑衔接方式，改了一版。两小时后定稿，老板改了两处。他想：这次没有分析面板肯定写不出来。

第二篇进来的时候，系统刚拆到一半，助理看着第一段就笑了——还是老样子：先承认困境再推演。他没等分析出完就动笔了。

助理这条路走通了。但另一个问题浮出来。

公司负责公众号的新媒体写自己的原创稿——不是改写创始人的内容，是独立产出。她觉得自己写得挺好：标题吸睛、结构分点、有数据有框架、结尾引导转化，都是"标准好文章"的要素。但她交上去，创始人说"不对"。

她改数据，改措辞，改案例。下一篇还是"不对"。

不是她改得不认真。是她脑子的"好"和创始人的"好"是两个标准——她的标准来自公众号生态教她的那一套，创始人的标准来自"从真实困境出发推演到认知收束"。她不知道自己的写作引擎和创始人是两套东西，她以为只是"写得还不够好"。

她把稿子丢进写作云。系统没替她重写，只是标出了差异：起点是热点而非困境、全文无物质锚点、结论与论据脱节。她第一次看到自己文章的叙事结构——和创始人放在一起对比，像两张完全不同的骨架。

她开始能看懂"不对"到底不对在哪里了。

后来新来的实习生问："老板的风格到底是什么？"助理想了想，直接讲了一遍：总是先说不知道什么，再用具体东西搭梯子，一步步推到结论，结尾一定回到开头的问题。但说完又补了一句：光知道这个没用，你得自己写一篇放进去让它评，评完你就知道你差在哪。

半年后，助理发现老板最近的随笔变了——以前那套手法做得越来越少，更多是直接抛判断然后平行举例。不是老板退步了，是他的思考方式在演化。而新来的另一个成员，学的还是半年前的总结。助理重新打开写作云，把老板这半年的文章过了一遍，带着大家一起更新了认知。

创始人在管理会上说："写作云不是帮一个人写好稿子的工具，是让整个团队能跟上我思考变化的方法库——尤其是让那些不知道自己写得不对的人，能自己看到。"

## 用户需求

### 自我发现

作为创始人，我希望分析自己的文章，系统展示我的叙事结构，这样我就能看见自己是怎么写的。

**验收标准：**
- 支持导入创始人自己的文章
- 自动拆解叙事单元，展示逻辑链条
- 多篇文章的分析结果可横向对比，呈现风格多样性

### 叙事分析

作为团队中需要改写创始人内容的成员，我希望把创始人的文章导入系统，系统自动拆解出叙事结构，这样我就能理解他的推演方式。

**验收标准：**
- 支持粘贴或上传创始人的原始文章
- 自动识别文章的叙事单元（起承转合等）
- 展示每个单元的逻辑功能：叙事动作、严密性支撑、逻辑效果
- 原文按段落切块，分析结果与原文段落对应排列

### 风格积累

作为团队中需要持续掌握创始人风格的成员，我希望系统能持续积累分析结果，不仅归纳当前风格，也能追踪风格随时间的变化，这样我不需要靠记忆判断"老板最近是不是换写法了"。

**验收标准：**
- 每篇文章的分析结果可存档
- 支持跨文章对比叙事结构异同
- 自动提炼高频叙事手法
- 按时间线展示风格变化趋势

### 稿件评审

作为写原创稿的团队成员，我希望把我的草稿提交给系统，系统能对比创始人的叙事风格指出偏离点，这样我在提交给创始人之前就能知道问题出在哪里。

**验收标准：**
- 提交草稿后，系统识别其叙事结构
- 对比创始人风格的差异维度（起点类型、物质锚点密度、逻辑严密性、收束方式等）
- 输出偏离点报告，指出根因而非替换措辞
- 偏离点可展开查看原文对照

### 团队传承

作为已经内化了方法的成员，我希望我能把分析结果和评审标准分享给新人，这样新成员能自己判断"这样写对不对"，而非靠资深成员逐篇审改。

**验收标准：**
- 分析结果和评审记录可分享给他人
- 新人提交的第一篇文章自动触发风格对比评审
- 支持导出风格总结文档和偏离案例集供新人学习

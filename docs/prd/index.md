# 量潮写作云 - 产品需求文档

## 主线故事

小陈是 CEO 助理，老板在内部发了一篇关于产品理念的随笔，小陈要把它改写成对外公众号文章。

### 第一次：跟着分析面板走

他把文章粘贴到写作云，系统拆出叙事结构。他一边看一边想：原来老板是这样推演的。

关掉面板开始改写，写到竞品部分卡住了——该怎么处理老板那种把对手比作"过时兵种"的类比？他翻回分析结果，对照老板在原文里的原话和逻辑衔接方式，把类比改成了客户听得懂的语言。两小时后定稿，老板改了两处措辞。

他心想：这次没有分析面板肯定写不出来。

### 第二次：认出模式

他又丢进去一篇复盘。系统刚拆到一半，他看着第一段就笑了——还是老样子：先承认困境再推演。和上次一模一样的手法。

他没等分析出完就动笔了。

### 第三次：自己就是那个方法

新来的实习生问："老板的风格到底是什么？"

小陈想了想，直接讲了一遍：总是先说不知道什么，再用一个具体东西搭梯子，一步步推到结论，结尾一定会回到开头的问题。他不需要打开写作云了。

团队叙事风格的一致性由此开始：不是靠模板统一，而是靠一批批人都这样内化过来。

## 用户需求

### 叙事分析

作为 CEO 助理，我希望把 CEO 的内部文章导入系统，系统自动拆解出叙事结构，这样我就能理解他的推演方式。

**验收标准：**
- 支持粘贴或上传 CEO 的原始文章
- 自动识别文章的叙事单元（起承转合等）
- 展示每个单元的逻辑功能：叙事动作、严密性支撑、逻辑效果
- 原文按段落切块，分析结果与原文段落对应排列

### 风格积累

作为 CEO 助理，我希望系统能积累多篇文章的分析，逐渐勾勒出 CEO 一贯的叙事风格，这样我就能越用越顺手，不再每次从零学起。

**验收标准：**
- 每篇文章的分析结果可存档
- 支持跨文章对比叙事结构异同
- 自动提炼高频叙事手法

### 团队传承

作为已经内化了方法的助理，我希望我能把分析结果和方法教给新成员，这样团队不会因为人员流动而丢失风格一致性。

**验收标准：**
- 分析结果可分享给他人
- 支持导出风格总结文档供新人学习使用

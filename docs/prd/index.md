# 量潮写作云 - 产品需求文档

## 主线故事

CEO 最近在整理自己的文章。他把随笔丢进写作云，系统一拆，他看到了自己的几种写法——有的先承认困境再推演，有的直接抛判断再举例。原来自己有这么多样式。

他让助理小陈也用上。

小陈第一次用，是把老板的文章粘贴进去。系统拆出叙事结构，他边看边想：原来老板是这样推演的。关掉面板开始改写，写到竞品部分卡住了——老板用了"过时兵种"的类比，他不知道怎么转成客户语言。他翻回分析结果，对照原文的逻辑衔接方式，改了一版。两小时后定稿，老板改了两处。他想：这次没有分析面板肯定写不出来。

第二篇进来的时候，系统刚拆到一半，小陈看着第一段就笑了——还是老样子：先承认困境再推演。他没等分析出完就动笔了。

后来新来的实习生问小陈："老板的风格到底是什么？"小陈想了想，直接讲了一遍：总是先说不知道什么，再用具体东西搭梯子，一步步推到结论，结尾一定回到开头的问题。

半年后，小陈发现老板最近的随笔变了——以前那套手法做得越来越少，更多是直接抛判断然后平行举例。不是老板退步了，是他的思考方式在演化。而新入职的另一个助理，学的还是他半年前的总结。小陈重新打开写作云，把老板这半年的文章过了一遍，和新助理一起更新了认知。

CEO 后来在管理会上说："写作云不是帮一个人写好稿子的工具，是让整个团队能跟上我思考变化的方法库。"

## 用户需求

### 叙事分析

作为 CEO 助理，我希望把 CEO 的内部文章导入系统，系统自动拆解出叙事结构，这样我就能理解他的推演方式。

**验收标准：**
- 支持粘贴或上传 CEO 的原始文章
- 自动识别文章的叙事单元（起承转合等）
- 展示每个单元的逻辑功能：叙事动作、严密性支撑、逻辑效果
- 原文按段落切块，分析结果与原文段落对应排列

### 风格积累

作为 CEO 助理，我希望系统能积累多篇文章的分析，逐渐勾勒出 CEO 一贯的叙事风格，这样我就能越用越顺手，不再每次从零学起。

**验收标准：**
- 每篇文章的分析结果可存档
- 支持跨文章对比叙事结构异同
- 自动提炼高频叙事手法

### 团队传承

作为已经内化了方法的助理，我希望我能把分析结果和方法教给新成员，这样团队不会因为人员流动而丢失风格一致性。

**验收标准：**
- 分析结果可分享给他人
- 支持导出风格总结文档供新人学习使用

# 叙事工程精髓

基于 material CLI 开发全过程的经验总结——特别是对过往认知的否定。这不是操作手册,而是设计哲学:工具链的形态,就是叙事工程哲学的形态。

## 一、被否定的过往认知

### 1. "AI 生成质量 = prompt 技巧"

定稿质量连续两轮"不如第一版",反复调整 prompt(补全信息、调整视角、约束节奏)均无效。真正根因:初稿只是素材的线性顺述。prompt 改对方向后质量才对齐——但**质量的上限由材料的组织状态决定,不由生成指令决定**。

> 工具链里没有"生成",只有"组织"。

### 2. "信息越多越好"

最初 distill 是纯聚合拼接(保留全部信息),被纠正为"删除次要信息";随后又发现过滤过度会毁掉初稿,于是"保留从宽"。

> **删除是取景,不是压缩**:砍掉的是干扰叙事的杂质,不是信息的数量。

### 3. "工具先于工作流"

按 CODE 循环设计命令时反复被纠正(产物编号、分组必须真实存在、初稿必须有用)——因为在设计"功能",而用户在设计"流程"。

> 工具只有成为用户工作流的镜像才有意义:随时记日志、按主题整理、再整合成文——material 的每一步都是写作习惯的投影。

### 4. "作品是叙事的基本单位"

命名决策链 Article ✗ → Document ✗ → Work △ → **Writing ✓**,本质是模型隐喻的否定:

- Work(作品)是**完成模型**("a work"默认已完成,素材期语义断裂)
- Writing(写作)是**过程模型**(素材、大纲、草稿、定稿都是"写作"的不同阶段)

> 叙事工程是过程模型,不是完成模型。

### 5. "定稿是一次生成的成品"

第一版定稿(直接基于素材自由生成)质量最高,但它绕过了整个链。最终对齐方案:初稿成文 + 定稿目标化重构。

> 成品是多层组织的结果,不是一次生成的瞬间——跳过任何一层,要么质量崩(链断),要么环节失效(初稿没用)。

### 6. "文笔决定文本质量"

各轮产物与第一版的差距不在措辞,而在**叙事线**(犹豫→设定→情绪→使命→品牌→勇气→告白)。

> 结构对了,文笔自然浮现;结构错了,文笔越好越像信息清单。

## 二、精髓:叙事是被组织出来的

> **叙事工程是把材料组织成叙事的过程——叙事不是被"写"出来的,而是被"组织"出来的:通过取舍、分层与重构,让藏在材料里的叙事自我涌现。**

### 组织的三态

| 组织动作 | 含义 | 在 material 中的体现 |
|----------|------|----------------------|
| **取舍** | 删除次要信息,让叙事线浮现 | distill 过滤四类杂质(过程叙述/用途/重复/情绪宣泄),保留从宽 |
| **分层** | 材料逐层组织,每层解决一个组织问题 | 素材→主题(归类)→初稿(成文)→定稿(目标化) |
| **重构** | 同一材料按不同目标产出不同叙事 | 创作谈 vs 品牌故事——叙事是目标导向的重构 |

### 人在环中,AI 是组织工具不是代笔

- 主题归属是可编辑的 YAML 建议,人工标注永不被覆盖
- 定稿在人的目标下重构(视角、结构、节奏为目标服务)
- 人的作用是**决策**(什么重要、给谁看、为什么写),AI 的作用是**执行组织**

> 对应创作日志里的话——"把不敢说的,变成可以说的":工程负责"可以",人负责"说"。

### 叙事的源头是生活流,产物是自我重构

创作日志本身就是叙事工程的完整样本:时间流里的情绪碎片(素材)→ 反复出现的母题(主题)→ 成文(初稿)→ 品牌故事(定稿)。而日志里写的正是"写作是叙事疗法为基础的重构平台":

> **叙事工程把未消化的经历,重组成可以审视、可以交付的故事。对内是释怀,对外是品牌,同一个工程。**

## 三、一句话总结

> **叙事工程 ≠ 让 AI 写得好;叙事工程 = 设计材料的组织过程,让叙事在取舍、分层与重构中自己长出来——而工程的目的,始终是把"不敢说的"变成"可以说的"。**

这也是为什么 material 的四步链(收集→分组→初稿→定稿)没有一步是"生成":每一步都是组织。

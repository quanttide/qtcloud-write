## 十条关键经验(速览)

0. **叙事工程 ≠ 让 AI 写得好**:叙事是被组织出来的(取舍/分层/重构),工具链里没有"生成",只有"组织"——详见 [narrative-engineering-essence.md](narrative-engineering-essence.md)。

1. **一个命令一个阶段一个产物**:产物编号稳定(01 收集 → 02 分组 → 03 初稿 → 04 定稿),归档与回溯成本最低。
2. **中间产物必须真实存在**:organize 曾只写 YAML 标注导致"分组形同虚设"——直到生成 `groups/` 文件成为 distill 的输入,环节才名副其实。
3. **质量问题的根因往往在上游**:定稿连续两轮"不如第一版",根因不是定稿 prompt,而是初稿只是素材顺述。修好初稿(成文),定稿自动对齐——不要在错误的下游打补丁。
4. **初稿必须有用**:初稿是定稿的底稿,必须完成"成文"(立意/结构/节奏),而不是素材的轻度改写。
5. **LLM 提示词只写通用判据**:不针对特定文本优化("删除公司信息"是错误示范;"动机 vs 用途""四类杂质"是正确示范)。
6. **过滤从严、保留从宽**:过滤只删四类明确杂质(过程叙述/用途/重复/情绪宣泄),信息宁可完整不可削减。
7. **定稿是重构不是修补**:让 LLM 按目标重新构思叙事(视角/结构/节奏),而不是"补全信息"——后者必然产出信息清单。
8. **LLM 只给建议,决策在人**:主题归属是可编辑的 YAML 建议,人工标注永不被覆盖。
9. **程序挂起先查代理**:ureq 不读环境代理,代理环境直连 GitHub 会无限挂起;curl 正常而程序超时 = 代理问题。
10. **文本质量必须实测对比**:每次 prompt 改动都要跑真实链路、归档产物、与上一版逐维度对比——质量不能靠感觉。

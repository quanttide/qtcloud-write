# LLM 提示词经验

material CLI 中三处 LLM 调用(organize 主题提取、distill 成文、express 定稿)沉淀的提示词经验。

## 1. 判据通用化,不针对特定文本

用户明确要求:"优化的时候不要针对特定文本优化提示词,而是要考虑一般情况。"

- **错误示范**:"删除公司信息"——只对当前案例有效,换个主题就失效,还会让模型学会偷懒(遇到"公司"就删,不管是否与主题相关)。
- **正确示范**:用通用判据——
  - "区分**动机与用途**:'为什么写'是主题核心应保留,'写完之后拿去做什么'属于事务性用途默认删除"——对任何主题、任何实体都成立。
  - "**四类杂质**":过程性叙述、用途信息、重复表述、即时情绪宣泄——用类别而非实例定义。

**检验方法**:把判据中的例子全部替换成另一个主题,判据仍成立,才是通用判据。

## 2. 过滤从严删除、保留从宽

过滤的默认倾向必须是**保留**:

- 删除从严:仅限四类明确杂质(过程性叙述 / 用途信息 / 重复表述 / 情绪宣泄),且情绪宣泄中可迁移的洞察仍要保留。
- 保留从宽:与主题相关的信息细节(人物、事件、设定、场景、动机、洞察、金句)**全部保留,信息宁可完整不可削减**。

**教训**:早期过滤判据过宽,把有信息量的细节("女主是主创,男主是产品")也删了,初稿干瘪,下游定稿质量直接崩盘——过滤过度比过滤不足危害更大,因为信息丢失不可逆(定稿阶段只能从素材补回,但素材在 prompt 中的权重低于初稿)。

## 3. 成文而非顺述

"统一表达"是个软要求,模型容易把它理解为"把素材改写一遍"——产出流水账。改为明确要求**成文**:

- 提炼立意:这篇文章想表达什么(素材里反复出现、最能打动人心的内核)
- 组织结构:按立意层层推进,有开头、发展、收束,主题分层展开
- 统一视角与语气,语言有节奏,金句自然浮现
- 显式声明:**"不是素材的顺述或改写,而是基于素材的完整作品"**

**效果**:同一素材,顺述版 43 行流水账;成文版 37 行立意明确、首尾呼应("把不敢说的,变成可以说的"开合)。

## 4. 定稿是重构,不是修补

定稿 prompt 经历了三个版本,效果差异显著:

| 版本 | 指令倾向 | 产物 |
|------|----------|------|
| 修补:"对初稿进行定稿:补全素材有效信息,调整结构语气细节" | 保守保留初稿结构 | 84 行平铺复述,品牌部分事务罗列 |
| 汇编:"补全信息"权重高 | 信息清单化 | 84 行主题章节,if 线/情绪日记等细节稀释叙事 |
| **重构**:"以初稿为底稿、素材为原材料,按写作目标重新构思——视角/结构/节奏为目标服务,事务性说明舍弃或转化为理念" | 目标驱动叙事 | 48 行叙事线,品牌升华为理念 |

要点:
- **让模型有创作自由度**:直接基于素材自由生成(第一版)质量最高——自由度是质量的来源;链式保留底稿概念,但重构指令要放开结构约束。
- **信息源 ≠ 结构源**:素材提供信息,目标决定结构;把两者分开写进 prompt。
- **事务性内容按目标转化**:品牌故事目标下,"发公司账号"这类事务说明应转化为理念表达("把'敢说'写进公司底色"),而不是原样保留。

## 5. 只给建议,决策在人

- organize 的主题归属只写入**未标注**条目,人工在 YAML 中的标注永不被覆盖——"分解主题"是心智过程,不外包。
- LLM 输出格式要可控:要求"只输出 YAML/定稿,不要解释";解析时容忍 ```yaml 围栏;解析失败时把原文回显给用户排查,而不是静默重试。

## 6. 一次只改一个变量

三轮定稿优化中,每轮只改一个 prompt 维度(信息权重 → 视角结构 → 成文要求),并用同一份素材、同一目标实测对比。若一次改多个变量,无法定位质量变化来自哪个改动。

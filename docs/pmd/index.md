# 量潮写作云 - 项目管理文档

## 路线图

### 当前阶段：核心链路打通（v0.1.x）

场景：CEO 助理"内部转对外"，核心链路为 分析 → 理解 → 改写 → 发布。

目前只跑通了前半段（分析+理解），后半段（改写+发布）尚未验证。

#### 已完成

- 场景定义：BRD/PRD 完成，CEO 助理角色确立
- 输入 fixture：CEO 内部随笔（article.md）
- 分析输出 fixture：叙事结构分析报告（report.md）
- 分析原型：原文段落 ↔ 叙事分析对照展示

#### 待验证

1. **对照改写原型**
   - 为什么：分析得再好，助理最终要落笔写。没有改写环节的原型，核心链路就断在半路，无法验证"分析真的帮到了改写"。
   - 验收：助理能用原型完成一篇 CEO 文章的完整对外改写流程，且 CEO 只改少量措辞即可定稿。

2. **风格积累数据**
   - 为什么：单篇文章的分析只能帮助理理解"这一次"，无法解决"越用越顺手"的问题。只有多篇 fixture 才能验证跨文章风格提炼是否可行。
   - 验收：基于三篇以上 CEO 文章的分析结果，能自动归纳出该 CEO 的高频叙事手法清单。

3. **对外输出模板**
   - 为什么：分析结果是中间产物，最终交付的是品牌故事或宣传册。没有输出模板，助理拿到分析报告后仍然不知道该怎么转。
   - 验收：给定一篇 CEO 内部文章，能按照模板结构输出一篇对外品牌故事初稿，助理在此基础上做少量调整即可发布。

## 阶段调整记录

### v0.0.x → v0.1.x：从"写作者工具"到"CEO助理工作台"

写作云最初定位为"写作者的灵感管理工具"，覆盖灵感收集、管理、激活、扩展。原型评估发现该定位角色模糊（"写作者"太宽泛）、场景不具体、无法判断需求真伪。

调整为 CEO 助理场景，原因：

- **角色明确**：CEO 助理有清晰的职责边界和痛点
- **问题可验证**：助理写不像 CEO → 需要理解叙事方法 → 需要分析工具 → 需要改写辅助，因果链清晰
- **价值可衡量**：交付物是对外品牌故事，好坏的判断标准明确（CEO 是否认可、改稿量是否减少）
- **数据可复用**：CEO 持续产出内部内容，助理持续对外发布，场景可持续

### 关键决策记录

- 叙事分析不是 AI 一键转义，而是辅助人理解，改写决策在人手里
- 产品简介从功能清单改为"场景-困境-救援"叙事结构
- 原型评估 4/10（C级）触发方向调整

# 量潮写作云 - 业务需求文档

## 场景：内部转对外

### 工作角色

- CEO：产出内部随笔和思考，也是产品的第一位用户——通过分析自己的文章看见叙事方式
- CEO 助理：需要对外宣发品牌内容，逐步内化 CEO 的叙事方法
- 新成员：需要快速上手，继承团队已有的风格认知
- 系统：组织叙事风格的基础设施，持续追踪、沉淀、传递

### 当前工作流（一对一，一次性）

1. CEO 在内部发了一篇随笔或复盘，内容是他的真实思考，结构由他当时的思路决定。
2. 助理收到文章，从头到尾读一遍。读完后知道"老板说了什么"，但不知道"老板为什么这样展开"。
3. 助理开始改写。靠感觉判断哪些是核心论点、哪些是内部语境需要转换、哪些是个人表达习惯需要保留。
4. 写到某个环节卡住了——比如老板用了一个军事类比，助理不确定该保留还是替换，因为不理解这个类比的逻辑功能。
5. 助理凭经验做了一版，发给 CEO。
6. CEO 改了几处，退回。
7. 助理修改，再发。反复 2–3 轮后定稿。时间窗口可能已经错过。

**每轮改稿的痛点：**
- 助理：每次都是新的猜测，不知道上次为什么被改、这次该怎么避。
- CEO：每次都要从零看稿、改稿，讲不清"为什么不对"，只能说"感觉不对"。
- 组织：没有沉淀，换一个人全重来。CEO 自己的风格变了，助理也不知道。

### 目标工作流（组织级，可持续）

1. CEO 把文章丢进写作云，看到自己的叙事结构——"原来我是这样写的"。他可以选择把文章分享给助理。
2. 助理打开文章，系统已拆好叙事单元。他不仅看到"老板说了什么"，还看到"老板为什么这样展开"——叙事动作、严密性支撑、逻辑效果清晰标注。
3. 助理开始改写。写到老板的军事类比时，能看到这个类比在原文中的逻辑功能（强制桥接：从具体现象到抽象本质），决定保留核心逻辑、换成客户听得懂的语言。
4. 定稿后 CEO 改了一两处措辞。助理记住了这个调整。
5. 第二篇文章进来时，助理发现"和上次的手法一样"——先承认困境再推演。他开始不依赖分析面板了。
6. 半年后 CEO 的风格变了，系统自动追踪了变化轨迹。新助理入职，直接从系统学习当前风格，不用请教已经离职的前任。

### 假设

如果存在这样一个平台，能够自动拆解 CEO 文章的叙事结构、持续追踪风格变化、沉淀为团队可继承的方法库，让每个成员都能理解、内化、传递，团队就能建立持久的叙事一致性。

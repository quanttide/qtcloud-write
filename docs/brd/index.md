# 量潮写作云 - 业务需求文档

## 场景一：灵感容器

### 工作角色

- 写作者：需要灵感进行创作
- 系统：存储和启发灵感

### 问题

触发：写作者需要创作，但灵感来去匆匆，很难捕捉。

现状：灵感往往在不经意间出现，比如散步时、聊天时、阅读时。但当时无法立即写作，事后想不起来。写作者需要一个地方来收集和存放这些灵感碎片。

困难：灵感是碎片化的，没有固定格式。灵感与具体创作情境关联，事后可能忘了当时的上下文。缺乏系统化的灵感管理方法。

后果：灵感流失，创作时无素材可用。写作需要从零开始，效率低。

### 假设

如果存在这样一个平台，能够让写作者随时随地记录灵感碎片，并按照某种方式组织关联，写作者就能积累自己的灵感库。

## 场景二：脱离情境创作

### 工作角色

- 写作者：需要在任意时刻开始创作
- 系统：提供创作上下文

### 问题

触发：写作者想在某个时刻开始创作，但需要重新进入状态。

现状：创作往往需要特定的心境和上下文。写作者需要先回忆之前的思路，找到切入点。这个过程很耗时，有时候干脆就不写了。

困难：过去的灵感与当前创作主题的关联不明显。需要某种方式帮助写作者快速建立当前主题与过去素材的联系。

后果：创作启动困难，写作效率低。

### 假设

如果存在这样一个平台，能够根据当前创作主题，自动推荐相关的灵感素材，写作者就能快速进入创作状态，流畅写作。

---

## 场景三：灵感激活

### 工作角色

- 写作者：需要被启发
- 系统：主动推荐灵感

### 问题

触发：写作者面对空白页面，没有思路。

现状：写作者有很多素材，但不知道从哪里开始。需要有人或工具来推动一下。

困难：灵感库内容太多，不知道哪些与当前主题相关。缺乏有效的触发机制。

后果：创作拖延，效率低下。

### 假设

如果存在这样一个平台，能够分析写作者的素材库，根据当前创作需求，激活相关的灵感碎片，写作者就能获得启发，流畅创作。

# express.rs — 表达:定稿

## 职责

实现产物链的 **04 定稿**:以初稿为底稿、分组素材补全信息,按写作目标重构,形成定稿 `materials/<主题>-定稿.md`。未提供 `--goal` 时,由 LLM 根据内容自动判断写作意图。

## 核心函数

| 函数 | 说明 |
|------|------|
| `build_finalize_prompt(topic, goal, draft, material)` | 定稿提示词:底稿 + 素材 + 目标 |
| `express(workdir, topic, goal)` | 读初稿与分组 → LLM → 写定稿 |

## 设计思路

1. **初稿是底稿,不是参考**:定稿基于 03 初稿(内容骨架与统一基调),而不是直接基于素材自由创作——否则初稿就成了多余的中间产物("初稿没有什么实际作用"的批评)。链式的意义在于:每一环都在上一环的基础上加工,04 的内容主线来自 03。
2. **素材补全被过滤的信息**:03 过滤掉的(如事务性用途)在定稿阶段按目标**可以回来**——比如品牌故事定稿需要公司信息,素材里有,初稿里没有,定稿从素材补回。信息不因过滤而丢失,过滤只影响初稿的表达,不锁死定稿的内容。
3. **重构而非修补**:早期版本让 LLM"对初稿进行定稿:补全素材、调整结构语气细节"——结果是初稿的平铺复述,质量远不如直接基于素材创作的第一版。修正为"以初稿为底稿,按写作目标**重构**结构与语气,素材有效信息自然融入,定稿是一篇完整、有层次的成品"。实测:84 行、有小标题组织、叙事有节奏,质量对齐第一版。
4. **目标缺省 = 自动判断**:`--goal` 缺省时用"根据内容自动判断写作意图"作为目标——写作意图从内容推断(如创作谈→第一人称真诚表达),不强制用户提供目标。
5. **链式校验**:定稿要求初稿存在,初稿要求分组存在,错误信息分别提示"先运行 material distill"和"先运行 material organize"——产物链顺序由文件依赖天然保证。

## 典型调用

```sh
material express 创作动机                                    # 自动判断意图
material express 创作动机 --goal "写一篇用于公司账号发布的品牌故事"  # 指定目标
```

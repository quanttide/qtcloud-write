# distill.rs — 提取:初稿

## 职责

实现产物链的 **03 初稿**:读分组产物 `groups/<主题>.md`,LLM **过滤次要信息 + 统一表达**,形成一篇信息完整、连贯成篇的初稿 `materials/<主题>.md`。

## 核心函数

| 函数 | 说明 |
|------|------|
| `build_draft_prompt(topic, aggregate)` | 初稿提示词:过滤判据 + 统一表达要求(通用,不针对特定文本) |
| `distill(workdir, topic)` | 读分组 → LLM → 写初稿(沿用分组的 front matter 与 sources) |

## 过滤判据(通用)

删除**从严**——仅限四类明确杂质:

1. **过程性叙述**:记录"正在做/打算做"的过程语句(如"我打算""我在尝试""最近"),只保留其中的结论或洞察
2. **用途信息**:素材将被用于什么、发布到哪里的说明(发布渠道、宣传用途、收益安排、目标账号),除非该用途本身是主题核心
3. **重复表述**:同一观点多次出现只保留最完整的一次
4. **即时情绪宣泄**:直接的情绪感叹与自我对话;其中可迁移的洞察保留

保留**从宽**——与主题相关的信息细节(人物、事件、设定、场景、动机、洞察、金句)全部保留,**信息宁可完整不可削减**。

## 设计思路

1. **初稿必须有用(本模块的第一原则)**:初稿是定稿的底稿。如果过滤过度、信息被削减,定稿质量必然下降——这是实测得到的教训:早期版本过滤判据过宽,把"女主是主创、男主是产品"这类有信息量的细节删掉,初稿变得干瘪,定稿远不如直接基于素材生成的版本。因此过滤"从严删除、从宽保留"。
2. **过滤 ≠ 压缩**:过滤的目标是去杂质(过程痕迹、事务性用途、重复、情绪噪音),不是信息压缩。统一表达把保留的内容组织成连贯文章,而不是要点列表。
3. **动机与用途的区分**:素材里"为什么写"(动机)是主题核心,保留;"写完之后拿去做什么"(用途)默认删除——这个判据对任何主题通用,不针对"公司/宣传"这类特定文本。
4. **输入是分组而非原始日志**:distill 只消费 `groups/` 产物,不自己聚合。这让 02 分组的价值落地,也让初稿的内容边界(某主题)由分组天然划定。
5. **front matter 透传**:初稿沿用分组的 `sources`(来源引用),保证任何产物都能回溯到原始日志条目。

## 典型产物

```markdown
---
topic: 创作动机
sources:
  - journal/2026-08-15.md#创作日志1
---
# 创作动机

写这部小说时,我刻意回避了"破镜重圆"……
(信息完整的连贯初稿)
```

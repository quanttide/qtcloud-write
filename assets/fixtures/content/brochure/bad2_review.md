# 问题清单

## 事实/逻辑问题

- **"万能钥匙"是伪承诺**：标题和全文反复强调"万能钥匙"——不存在一种思维框架能解决所有复杂问题。这个表述是营销夸张，经不起追问。
- **核心概念悬空**：全文反复提"通用建模思维""底层逻辑"，但从未用一句话说清它到底是什么。第11行写了"定义问题-拆解要素-构建模型-验证优化"，但这不是一个思维框架，是任何方法论共有的步骤描述，没有区分度。
- **门槛矛盾**：第11行说"无需编程基础和数据专业背景"、"普通人也能轻松入门"，第16行立刻出现LTV/CAC、成本效益分析——没有基础的人看到这些术语不会觉得"轻松"。
- **学员反馈不可验证**：第40-48行的三段学员反馈全部匿名（"有学员""有同学""有基础的同学"），无具体身份、无原话引用、无学习前后对比。对比 good 文章的物质锚点（助理小周的原话、工作日志句子），这个差距很大。
- **论证是循环**：上这门课 → 获得建模思维 → 解决复杂问题。但"建模思维"从未被定义，等于"上这门课就能解决复杂问题"——没有独立论证。

## 叙事风格对比（vs style.md + good 范文）

### 起点：无困境，只有泛化痛点

good 文章的起点永远是**具体的个人困境**：

| 文章 | 起点 |
|------|------|
| good1 | 陷入具体场景，不知道自己在做什么 |
| good2 | 昨天还在想，今天就发现白干了 |
| good3 | 工作日志里一句无意识的句子 |
| good4 | 最近持续给自己减负 |
| good5 | 网络环境可信任程度持续降低 |
| bad2 | "我们总以为学个Python、SQL…到头来发现还是无从下手" |

bad2 的起点是标准营销文案的"泛化痛点"——没有具体的人、没有具体的事、没有时间地点。这种开头读者知道是套路，不会当真。

### 物质锚点：无

good 文章每一篇都有不可替换的物质锚点：

| 文章 | 锚点 |
|------|------|
| good1 | 战棋游戏、qtgame-war、qtgame-tycoon |
| good2 | 助理小周的原话 |
| good3 | 工作日志原文"啊不对，是从客户的角度设身处地" |
| good4 | 预留的文章、技术助理、交友软件、小说 |
| good5 | 交友软件、微博、小红书、短剧 |
| bad2 | 无 |

bad2 全文没有一个具体的、可验证的人、事、物。学员反馈是匿名的，课程内容是没有名字的案例，连"老师"都没有身份。文章可以换任何一家培训机构的名字发布。

### 叙事意图：卖课 vs 推演/表达

| 维度 | good 文章 | bad2 |
|------|----------|------|
| 目的 | 理清认知 / 传达态度 | 销售课程 |
| 结构 | 认知推演 / 平行例示 | 痛点→方案→卖点→见证→CTA |
| 读者感受 | "这个人在认真思考" | "这个人在卖东西" |
| 可替换性 | 换作者名就不成立 | 换机构名也能发 |

### 文风

- bad2 大量使用 emoji（✨✅️🎯👇）、感叹号、营销黑话（"底层逻辑""万能钥匙""核心竞争力""天赋"）
- good 文章极少使用这些手法
- bad2 每段都很短、换行频繁——这是公众号转化文案的标准格式，目的是降低阅读门槛、保持滑动节奏。good 文章段落较长、信息密度高。

### 和 bad1 的对比

bad1（千问奶茶文）至少在做分析，有数据、有框架、有论证过程，问题出在数据不准和逻辑不严。bad2 连分析都没有——全文没有给出任何一个完整的思维案例、没有定义核心概念、没有可验证的信息。

bad1 的问题是"分析错了"；bad2 的问题是"没分析"。

## 总结

**最严重的问题：全文无物质锚点、无具体案例、核心概念未定义。** 如果目标是模拟作者风格（style.md 定义的札记/故事模型），bad2 在所有关键维度上都不匹配——起点泛化、无锚点、意图错位。它是一篇标准的课程销售文案，不属于 style.md 框架覆盖的任何文体。
